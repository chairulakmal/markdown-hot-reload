Install mhr on Linux

mhr is a read-only GitHub-flavoured markdown viewer. There are four ways to install it: the snap, which is one command and updates itself, the .deb for Ubuntu 24.04 and Debian 13, a tarball for every other x86_64 distribution, and cargo install mhr, which builds it from source. This page covers all four, including how to check a download against its published checksum and how to update or remove each one.

What is mhr

Run mhr notes.md and a window opens with the rendered markdown. Every time you, an editor, or an agent saves that file, the window updates in place. There is no editing surface, and mhr never writes to the file it watches.

It is safe to point at a file you did not write. mhr never contacts the network, because its webview's Content-Security-Policy sets connect-src 'none', and it always escapes raw HTML in a document rather than executing it. A document can come from an editor, an agent, or a repository you do not control, so every document is treated as untrusted input. The tests that guard each claim are listed in the README's Safety section.

Command mhr <file.md>, one file argument, required
Architecture x86_64 (amd64) only, no arm64 build yet
Licence MIT

Which package to use

Use the snap unless you have a reason not to. It is the only package that updates itself. The other three are installed once and stay at that version until you repeat the steps by hand.

Installing non-interactively? If a script, a CI job, or an agent is doing the install rather than a person at a desktop, prefer cargo install mhr instead. It is one command, with no release page to read, no filename to template, and no checksum step, and it builds the binary from the published source on crates.io rather than asking you to trust a prebuilt one.

The snap, recommended

The snap runs on any distribution that has snapd. Ubuntu includes snapd by default. The snap bundles its own WebKitGTK, so it does not depend on what your system has installed: 

sudo snap install markdown-hot-reload
sudo snap alias markdown-hot-reload.mhr mhr

The second command creates the mhr command. It is needed because the snap installs itself as markdown-hot-reload.mhr. A bare mhr alias needs Snap Store approval, and that request is currently under review. The alias command works on your own machine whatever the Store decides.

Then open any markdown file:

mhr notes.md

Running the snap from a terminal can print lines like Could not open /sys/class/dmi/id/chassis_type or This call is not available inside the sandbox. These come from GTK probing hardware and desktop details that Snap's confinement blocks on purpose. They are harmless: the window still opens and renders the file normally, so it is safe to ignore them.

Updating

snapd refreshes installed snaps on its own, usually within a day of a new release, so there is normally nothing to do. To update immediately instead of waiting: 

sudo snap refresh markdown-hot-reload

The Snap Store listing shows the version currently published.

Removing

sudo snap remove markdown-hot-reload

This also removes the mhr alias created for it. mhr writes no configuration files and no cache, so nothing else is left behind.

The .deb, for Ubuntu and Debian

Choose the .deb if you would rather install through apt and use your system's own WebKitGTK than a bundled copy. It installs the command as mhr straight away, with no alias step.

Requirements

The .deb needs Ubuntu 24.04 (Noble Numbat), Debian 13 (trixie), or newer, on x86_64. It links against the t64 builds of GTK and GLib, which earlier releases do not have. On an older release, use the snap or the tarball instead.

All four steps in one block

Each step is explained on its own below. To install without reading further, run these lines in an empty directory: 

TAG=v0.1.1
BASE=https://github.com/chairulakmal/markdown-hot-reload/releases/download

curl -LO "$BASE/$TAG/SHA256SUMS"
curl -LO "$BASE/$TAG/mhr_${TAG#v}-1_amd64.deb"
sha256sum -c SHA256SUMS --ignore-missing   # must print OK, stop here if it does not
sudo apt install ./mhr_*.deb
mhr --version                              # prints the installed version
The .deb does not update itself. There is no apt repository for mhr, so apt upgrade will never bring you a new version. See Updating below. The snap above avoids this.

1. Pick a release

Open the releases page and note the tag you want, for example v0.1.1. The tags v0.1.0-alpha and v0.1.0-beta are marked Pre-release on purpose. That was the plan during early development, not a sign anything was broken.

2. Download the package and its checksums

Set TAG to the tag you picked, then download both files into the same directory: 

TAG=v0.1.1

curl -LO "https://github.com/chairulakmal/markdown-hot-reload/releases/download/$TAG/SHA256SUMS"
curl -LO "https://github.com/chairulakmal/markdown-hot-reload/releases/download/$TAG/mhr_${TAG#v}-1_amd64.deb"

${TAG#v} strips the leading v, because the tag is v0.1.1 while the file is mhr_0.1.1-1_amd64.deb. SHA256SUMS covers the .deb and the tarball. It does not cover the "Source code" archives GitHub generates on its own.

3. Verify the checksum

Check the download against the checksum GitHub Actions produced when it built the release: 

sha256sum -c SHA256SUMS --ignore-missing

--ignore-missing skips the tarball's line, since you only downloaded the .deb. The command must print OK next to the package's filename. If it prints FAILED, or reports no such file, do not install the package. Delete it and download it again.

4. Install it

apt resolves the WebKitGTK and GTK dependencies from your system's own repositories, so there is no separate download step for those: 

sudo apt install ./mhr_*.deb
apt may print N: Download is performed unsandboxed as root as file '...' couldn't be accessed by user '_apt'. This is a warning, not an error. The _apt sandbox user cannot read files inside your home directory, and the install still completes correctly. To avoid the warning, move the .deb to /tmp and run the same command there.

Confirm the install, then open any markdown file:

mhr --version
mhr notes.md

Updating

There is no apt repository for mhr, so apt upgrade never brings a new version. Repeat the steps above with a newer tag from the releases page; apt install replaces the old package with the new one.

Removing

sudo apt remove mhr

mhr writes no configuration files and no cache, so nothing else is left behind.

The tarball, for other distributions

Every release ships a plain x86_64-unknown-linux-gnu tarball. Use it on any distribution that is not Debian based and does not run snapd. It contains the mhr binary, the README, and the licence, inside a directory named after the version: 

TAG=v0.1.1
BASE=https://github.com/chairulakmal/markdown-hot-reload/releases/download
DIR="mhr-${TAG#v}-x86_64-unknown-linux-gnu"

curl -LO "$BASE/$TAG/SHA256SUMS"
curl -LO "$BASE/$TAG/$DIR.tar.gz"
sha256sum -c SHA256SUMS --ignore-missing   # must print OK, stop here if it does not
tar xzf "$DIR.tar.gz"
sudo install -m 755 "$DIR/mhr" /usr/local/bin/mhr

The binary needs WebKitGTK 4.1, which the tarball does not carry. Install it from your own package manager. The package name varies between distributions, so search for webkit2gtk. Then confirm the install: 

mhr --version

Updating

There is no update mechanism. Download and verify a newer release the same way as above, then overwrite the binary: 

sudo install -m 755 "$DIR/mhr" /usr/local/bin/mhr

Removing

sudo rm /usr/local/bin/mhr

mhr writes no configuration files and no cache, so nothing else is left behind.

From crates.io, with cargo

mhr is published on crates.io, so cargo can build and install it directly. Choose this if you already have a Rust toolchain, or if you want to read the source you are running. It compiles on your machine, so it takes minutes rather than seconds, and it does not update itself.

Two prerequisites first. Rust 1.88 or newer, which rustup installs, and the WebKitGTK development packages, because the window is a WebKitGTK webview. On Ubuntu and Debian: 

sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev pkg-config
Install those three packages before you run cargo. Without them the build fails at the linker, and the error does not name the package that is missing.

Then install the crate and open a file:

cargo install mhr
mhr --version
mhr notes.md

cargo puts the binary in ~/.cargo/bin, which rustup already adds to your PATH.

This is the only install path that is not built here, so it is also the only one that could work beyond Linux. Linux is the platform mhr is released and tested on. macOS and Windows are untested rather than supported, so treat a build there as something that may work rather than something that should.

Updating

cargo install mhr

This reinstalls whatever is newest on crates.io, overwriting the old binary.

Removing

cargo uninstall mhr
